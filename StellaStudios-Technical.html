01 / overview

StellaStudios treats short-form video creation as a multi-stage workflow rather than a single generative request. A GPT node produces structured metadata, and specialized nodes use that metadata to generate video and narration, select and process music, create subtitles, assemble the media, and archive artifacts.

The architecture separates creative generation from deterministic post-processing. External models supply creative material; Python and FFmpeg handle orchestration, file movement, audio processing, subtitle formatting, encoding, and archival.

Scope note: the source confirms the major components and intended sequence. It does not establish current end-to-end reliability, consistent model output, concurrency safety, or an active unattended publishing service.

02 / creative metadata

The GPT node calls the OpenAI Chat Completions API in JSON mode and expects five fields: title, description, video, voice, and music. Creative presets provide reusable constraints, while model configuration is managed separately. The environmental preset targets a short vertical scenic clip with coherent motion, consistent lighting, and a calm tone.

The node checks that required fields are present before storing the result. The prompt and schema describe more constraints than the implementation independently validates, so required-key presence should not be confused with full schema enforcement. Prompt wording also cannot guarantee that an external model follows every visual instruction.

03 / video generation

The video node reads production metadata, selects the relevant configuration, submits the scene description to an external video-generation service, waits for completion, retrieves the result, and saves the video for downstream use. This keeps the creative specification separate from later media assembly.

The intended properties include stable perspective, continuous motion, consistent lighting, and no abrupt scene changes. These are prompt goals, not guarantees of the generated footage. Actual quality remains dependent on the service and individual generation.

04 / narration

The narration node sends the generated voice field to an external text-to-speech service, applies configured voice and synthesis parameters, and saves the returned audio artifact. This stage is independent of video rendering and hands the audio file to later stages.

Prompt constraints specify a brief, understated delivery and fragment structure. The generated text and service output can still vary, so downstream timing and composition must work with the artifacts actually returned.

05 / soundtrack processing

The music node does not generate a soundtrack from the metadata's music description. It selects an existing track from a local collection, inspects its duration, chooses a short segment, and uses FFmpeg to extract it. Loudness normalization and fade processing are applied before the resulting clip is passed to assembly.

This is a hybrid design: the metadata can describe intended musical character, but the inspected implementation uses a reusable local asset pool rather than conditioning music generation on that description.

06 / subtitle generation

The subtitle node removes the whisper marker from narration text, splits the remaining text into phrases, measures the narration duration, and distributes those phrases across the timeline. It writes styled Advanced SubStation Alpha (ASS) subtitles with configured typography, outlines, and fade effects.

Timing is estimated at the phrase level. The implementation does not establish phoneme-level or word-level alignment, so subtitles may not match every spoken word precisely.

07 / audiovisual assembly

The stitching stage combines the video, narration, soundtrack segment, and subtitle artifact. FFmpeg handles audio preparation and mixing, source-level adjustments, optional subtitle burn-in, optional text watermarking, and H.264 video with AAC audio encoding.

Keeping assembly separate from generation allows the system to process available artifacts through a conventional media pipeline. The final result depends on the correct artifacts being associated with the same production run.

08 / orchestration and storage

The coordinator invokes metadata generation, soundtrack processing, speech synthesis, subtitle generation, video generation, stitching, and archiving. A pending directory provides intermediate handoffs, and the archiver organizes artifacts after assembly. A separate uploader process is part of the wider project.

Not every stage receives an explicit production identifier. Some stages independently discover the latest metadata or clear shared pending directories. Concurrent runs can therefore interfere with each other or associate an artifact with the wrong run. Per-job identifiers and isolated workspaces would strengthen this design.

09 / diagnostics

The project includes logging around configuration, stage execution, artifact handling, and errors. This makes individual pipeline stages easier to inspect than a single opaque process. Logging alone, however, does not provide robust retries, transactional handoffs, or recovery after partial failure.

10 / verification and limits
  • Metadata validation: required fields are checked, but the full prompt and schema contract is not comprehensively enforced by code.
  • Visual quality: prompt constraints express desired output and do not guarantee temporal or geometric consistency.
  • Subtitle timing: phrase timing is estimated rather than aligned to word-level timestamps.
  • Soundtrack selection: a local track pool is used; the music description is not used to generate a new score.
  • Run isolation: shared pending storage and latest-metadata discovery create concurrency risks.
  • Operational status: the scheduled cycle is currently paused. Source inspection does not prove current end-to-end operation or production uptime.
  • Testing: this review is based on source and configuration inspection, not a comprehensive end-to-end test report.
11 / engineering priorities

The most direct hardening work is to validate metadata against an executable schema, isolate every run with a unique job identifier, bind all artifacts to that identifier, and define stage-level timeout, retry, and recovery behavior. Automated end-to-end tests should verify that the assembled video uses the expected narration, music, and subtitle artifacts before it is approved for publication.

12 / summary

StellaStudios demonstrates a modular audiovisual workflow that joins generative services with conventional media processing. Its distinguishing engineering work is in the structured handoffs, specialized nodes, and assembly process. The next maturity step is not adding more model calls, but improving validation, run isolation, recovery, and verification.
