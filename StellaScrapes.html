Make public records easier to search and use

StellaScrapes turns supported municipal open-data records into structured results that can be reviewed, cleaned, and exported. Search by location, record type, trade, or date range without building a separate API request for every dataset. The current MVP retrieves data through Socrata; broader coverage and commercialization remain on hold pending proof of sale.

Python Socrata Open Data API Registry-driven search CSV and Excel export
how it works

Use the local browser interface for quick searches and exports, or the Python command-line interface for search, catalog maintenance, and discovery tasks. The browser app is a local tool, not a hosted multi-user service.

query syntax
[trade] [data type] in [city] → hvac permits in seattle [trade] [city] last [N] days → roofing chicago last 30 days [city] [data type] → austin foreclosures [city] [trade] → los angeles electrical data types: permits, foreclosures, code_violations, business_licenses, tax_liens, evictions
example commands
$ python main.py search "hvac permits in seattle" $ python main.py discover # find all US Socrata domains $ python main.py catalog # map datasets per domain $ python main.py cities # list registry coverage

the problem

Public records can be useful for market research, but each publishing agency organizes its datasets differently. Field names, dataset identifiers, and update practices vary, making it difficult to compare or reuse records across locations.

StellaScrapes interprets a plain-English query, resolves it against a configurable dataset registry, and retrieves records from supported Socrata sources. Separate discovery tools catalog potential datasets for review. Finding a dataset does not automatically make it supported, so new sources still need validation and integration.

business use

For research teams and businesses, the value is less time spent finding datasets and cleaning inconsistent records. Permit data can support local construction research or give a team records to review for potential leads. A score helps sort results; it does not establish that a record is a qualified prospect.

The registry separates much of the source configuration from the search logic. That gives the project a path to expand coverage without writing an entirely separate search implementation for every location. It does not mean every city or record category is currently supported.

what it helps with
  • Plain-English searchQueries such as hvac permits in seattle are parsed into location, record type, trade, and date filters, then resolved against configured datasets.
  • Dataset discoveryCataloging tools inspect Socrata domains and dataset metadata to identify potential sources for later review. Discovery is a starting point, not automatic proof of support.
  • Central registryA JSON registry maps locations and record categories to dataset IDs and candidate field names, keeping source configuration separate from query handling.
  • Permit cleaning and prioritizationCleaning rules normalize selected fields, remove duplicates, and assign a rules-based priority score to help people review records. Scores are not validated predictions of buyer intent or revenue.
  • Portable exportsSearch and cleaning workflows can produce CSV and formatted Excel files for analysis or handoff.

The browser interface is built with Express and standard HTML, CSS, and JavaScript. A separate Python CLI exposes search, discovery, cataloging, tests, and the preliminary prospecting workflow. Both interfaces remain local and depend on the current registry and supported retrieval paths.

status and limits

Functional MVP; further development and commercialization are on hold pending proof of sale. Socrata is the operationally implemented retrieval platform in the inspected search paths. Four additional platform types appear in configuration but do not have retrieval adapters. The directory-based buyer-prospecting module is parked after the target source blocked requests during checks in July 2026.

Project documentation advertises 66 cities and 15 data types, but those figures describe intended or configured coverage, not a guarantee that every combination works. Discovery and field mapping are heuristic and require verification. The Node.js Socrata path has a 5,000-record request limit and a 30-second timeout.

Previously recorded test runs reported 37 JavaScript checks passing, plus 43 Python passes and three warnings. These are historical results, not a fresh test run or proof of end-to-end reliability.
