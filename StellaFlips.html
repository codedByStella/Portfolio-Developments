overview

The Grand Exchange changes constantly. StellaFlips was designed to make market research easier to scan by combining buy and sell estimates, accounting for GE tax in profit calculations, and filtering recommendations using recent and weekly price trends. Recommendations were decision support, not guarantees of a completed trade or realized profit.

Its documented feature set included investment tiers, a separate high-volume category for common bulk goods, a best-picks summary, and an item lookup flow that could suggest likely matches and ask for clarification when a query was ambiguous. The version notes also describe ten-second price-detail refreshes while recommendation lists stayed locked for an hourly interval.

why this matters

StellaFlips combined Grand Exchange prices, tax-aware profit estimates, and recent price trends in Discord so players could compare candidate flips without manually checking each item.

The implementation is documented for Old School RuneScape item research. It was not a commercial trading platform, and its recommendations did not guarantee that a trade could be completed at the displayed price.

what it tracks
  • Tiered flip detection - 7 channelsItems are bucketed by required investment (500k–1m up through 500m+), each with its own minimum profit-per-limit-cycle threshold and liquidity floor, so recommendations stay realistic for that budget tier rather than showing the same top items everywhere.
  • Bulk commodity tracking - 20 categoriesOres, bars, fletched goods, potions, runes, hides, hunter proceeds, gems, and more - each category continuously re-ranked by profit, independent of the tiered-investment logic.
  • High alch calculatorPulls live nature rune price from the GE and computes true alching profit (high alch value − buy price − rune cost) per item and per buy-limit cycle, sorted descending.
  • Best Picks aggregationA meta-view that pulls the single best-performing item across all seven investment tiers, plus the best 10 bulk items by profit-per-limit - the "if you only check one channel" summary.
  • Item lookup with fuzzy matchingType a partial or misspelled item name (or a community abbreviation like "ags" or "whip") in a dedicated channel and get a live-updating price card. Ambiguous matches trigger a disambiguation prompt instead of guessing wrong silently.
  • Self-healing message layerA 0.5-second loop independent of the main data cycle checks whether any bot message has been deleted and, if so, instantly reposts it from an in-memory cache - no wait for the next full data refresh.

engineering detail

Filtering out bad advice, not just bad data

The naive version of this bot just sorts by profit-per-item and calls it done. That's actively dangerous advice in a live market - an item can show a huge historical profit margin because its price is actively collapsing, and by the time a human reacts, the spread is gone.

So every candidate item runs through a trend classifier before it's allowed into a recommendation list: recent price is compared against its 24-hour and 7-day historical average, with a cascading fallback across timestep granularities (5-minute → hourly → 6-hour) so thin-volume items still get a usable read instead of no data at all. Anything trending down more than 3% on either window is rejected outright, regardless of how good the raw profit number looks.

trend-based rejection (simplified from production)
# Only recommend items that are STABLE or GROWING - # a crashing item with a good spread is a trap, not a flip. if trends: daily_trend = trends.get('daily', {}).get('trend', '') weekly_trend = trends.get('weekly', {}).get('trend', '') if 'Crashing' in daily_trend or 'Crashing' in weekly_trend: continue # reject regardless of profit margin

The surviving changelog supports trend comparisons, last-known pricing, and price-freshness context, but it does not independently establish that every historical fallback or outlier threshold behaved correctly in all cases.

architecture notes
  • Lock-and-refresh channel stateEach tier's top-10 list locks for a full hour once populated, rather than reshuffling every 10-second poll - the underlying price data still updates live within that locked list, but item selection only re-runs hourly, so the channel doesn't feel like it's flickering.
  • GE tax and buy-limit modelingAll profit figures net out the Grand Exchange's 2% sell tax (above the untaxed threshold) and multiply through each item's actual 4-hour buy limit, so "profit per limit cycle" reflects what's realistically extractable, not a theoretical single-unit margin.
  • Global blacklist~80 items - seasonal cosmetics, ultra-low-volume uniques, and known-unreliable flips - are hard-excluded so the bot can't recommend something technically profitable but practically untradeable.
  • Dual-loop recovery designA fast 0.5s loop handles message-deletion recovery from cache; the slower 10s loop handles the actual market re-poll and full embed rebuild - separating "keep the channel alive" from "refresh the data" so a Discord API hiccup on one never blocks the other.
  • Single fetch, many consumersWith 30+ channels and thousands of items in play, calling the price API separately per channel would multiply requests for no benefit and risk getting rate-limited. Instead, one full snapshot (mapping, prices, volumes) is pulled per cycle and shared across every tier, every bulk category, and the Best Picks aggregation - the API gets hit once, the data gets reused everywhere.
