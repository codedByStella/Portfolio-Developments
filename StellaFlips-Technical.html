01 / review basis

StellaFlips was a Discord-based market research tool for Old School RuneScape. The surviving #version-changes history documents releases 1.0.0 through 1.0.3 and describes iterative work on profit calculations, price refreshes, recommendation lists, Discord message updates, item search, trend summaries, images, and calculators.

Important limitation: the source code and running Lightsail instance are not available for a fresh audit. This page is based on the supplied version history. It does not claim that every listed feature was reliable in every condition or that the service can currently be relaunched.

02 / profit calculations

The changelog for version 1.0.1 records a correction to profit calculations that had omitted Grand Exchange tax and were affected by numeric truncation. This matters because a small arithmetic error can change the ranking of candidate trades.

The same release notes describe moving list ordering toward maximum profit per item after earlier ROI and buy-limit sorting surfaced unsuitable recommendations. The version history documents the intended corrections, but no source or independent test results are available here to verify calculation accuracy across all item types and price ranges.

03 / price refresh and list locking

The version history describes a split between frequently refreshed item details and a more stable recommendation list. Price details were intended to refresh every ten seconds, while the selected list stayed locked for an hourly interval. The list could continue scanning when fewer than ten recommendations were available and remain locked when full.

This design addresses a practical usability problem: rapidly changing the recommended items can make it difficult for a player to act on a previously seen opportunity. The changelog supports the intended refresh and lock behavior, not a measured guarantee of price freshness or execution quality.

04 / recommendation categories

The documented categories included budget or investment tiers, a high-volume list for common bulk goods such as logs, ore, fish, implings, and runes, and a Best Picks summary separating individual flips from bulk purchases.

The changelog also records filtering out categories of unsuitable or noisy recommendations, including certain clue-scroll items, low-dose potion variants, and items considered too slow or erratic. A blacklist and dedicated bulk categories were practical curation choices intended to improve the usefulness of the lists.

05 / trend classification

The version notes describe daily and weekly high/low summaries, trend lines relative to average prices, and a more readable classification of growing, stable, or crashing items. The documented rule compared current average price with daily and weekly averages: decreases of 3% or more were classified as crashing, increases of 3% or more as growing, and values between those thresholds as stable.

The changelog says items classified as crashing were excluded from recommendations. This is a heuristic to reduce exposure to obvious downward movement, not a promise that a recommended item cannot lose value. Market conditions can change between a data update and a user's trade.

06 / item lookup and user experience

The item lookup feature returned a formatted information card for a named item, including support for common abbreviations such as SGS and ACB. Later notes describe best-match suggestions, automatic-correction disclosure, and a clarification wizard when a search term was too broad or ambiguous.

These improvements made the interface more forgiving of shorthand and imperfect queries. The changelog also records adding item images, standardizing card layouts, improving image fallbacks, and addressing naming inconsistencies that caused the wrong image or no image to appear.

07 / Discord message management

Version 1.0.1 records replacing a webhook-based posting approach with a Discord bot integration so the program could edit a persistent message rather than repeatedly posting new lists. The changelog describes fixes for cases where failed message edits caused duplicate posts, as well as message-ID recall and repost behavior after a user deleted a managed message.

The version history also describes channel organization, more descriptive headers, separate lists for bulk and tiered recommendations, startup channel clearing, and handling Discord's whitespace trimming around images. These are documented implementation goals and fixes, not an independent guarantee of delivery or recovery latency.

08 / image caching and additional calculators

The changelog records thumbnail caching to reduce repeated image acquisition, corrections to image paths and naming conventions, and moving image hosting and retrieval away from repeated CDN caching behavior. It also documents a high-alchemy calculator sorted by profit and a potion-decanting calculator.

The available history does not establish current image-hosting availability, API credentials, service costs, or whether external resources remain compatible.

09 / current limits
  • The source code is unavailable for fresh inspection.
  • The Lightsail instance is parked and is not being recovered for this portfolio entry.
  • The surviving changelog documents features and development history, not current uptime.
  • No independently verified profit, user count, uptime, latency, or trading-success metrics are claimed.
  • Trend filters and price estimates cannot guarantee that a trade remains profitable when a user acts.

The value of this project as portfolio evidence is the documented progression from a primitive recommendation list toward more careful calculations, stable list presentation, trend-aware filtering, and more usable Discord interaction.
