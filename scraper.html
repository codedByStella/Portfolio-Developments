overview

Most US cities publish permits, licenses, and code enforcement data through Socrata — but every city's dataset has different field names, IDs, and quirks. Anyone wanting cross-city lead lists (contractors chasing permit activity, analysts tracking foreclosures) either pays for an aggregator or hand-writes a scraper per city.

This platform treats "which city, which dataset, which filters" as a single natural-language query, resolves it against a city/dataset registry, and returns cleaned, scored, exportable records — with a separate discovery subsystem that can find and catalog every US Socrata domain automatically rather than relying on a hand-maintained list.

why this matters

Permit and license data is genuinely public — but that doesn't mean it's usable. Every city ships it through a different portal, with different field names and no consistent structure, so the practical barrier to using this data isn't legality, it's plumbing. That plumbing problem is exactly what companies selling into newly-permitted properties — insurance, security systems, financing, landscaping, home services — pay someone to solve, because "call the homeowner who just pulled a permit before your competitor does" is a real, time-sensitive sales motion.

The registry-plus-discovery design is the part that actually scales that: onboarding a new city is a data-lookup problem, not a new integration to hand-code, which is the difference between a tool that covers three cities forever and one that can grow into national coverage without a rewrite.

what it does
  • Natural-language query routingQueries like hvac permits in seattle, roofing chicago last 30 days, or austin foreclosures are parsed into city, dataset type, trade filter, and date range — no need to know the underlying API shape.
  • Domain discoveryPages through Socrata's national API to collect every US domain publishing open data, so the platform's coverage isn't capped by a manually maintained city list.
  • Dataset catalogingMaps every dataset available on a given domain (or all discovered domains) so new cities can be onboarded without manually hunting for the right dataset IDs.
  • Lead scoringPermit records are scored on lead quality — for example, a permit with no listed contractor is flagged as an open opportunity — and the top-scoring leads are surfaced immediately in the CLI output, not buried in a spreadsheet.
  • Dual exportEvery result set writes to both a clean CSV and a formatted Excel workbook, so output is equally usable for scripting or for handing directly to a non-technical buyer.

The registry itself is what makes new-city onboarding cheap: each city config maps its display name, state, and per-dataset IDs against Socrata's API shape. Adding a city is filling in that mapping, not writing a new scraper — the query parser, lead scoring, and export logic don't change at all when coverage grows.
